# Collapse most upstream TypeSafe exceptions into two generic types

`langchain-typesafe` raises nine distinct exception types (`TypeSafeBadRequestError`, `TypeSafePermissionDeniedError`, `TypeSafeUnprocessableEntityError`, `TypeSafeInternalServerError`, `TypeSafeAPIConnectionError`, `TypeSafeAPITimeoutError`, etc.), each carrying different attributes. `DartmouthDecisions` reuses the package's existing `InvalidKeyError`/`ModelNotFoundError` for the two cases every other Dartmouth component already distinguishes (authentication, model-not-found), and collapses every remaining upstream exception into two new types: `DecisionAPIError` (generic) and `DecisionRateLimitError(DecisionAPIError)` (carrying `.retry_after_ms`, since rate limits are common enough to warrant programmatic handling). No `TypeSafe*` exception type is ever raised to a caller of `DartmouthDecisions`.

We considered mirroring the full nine-type hierarchy with `Decision*Error` equivalents, but rejected it as speculative generality: the rest of the codebase has operated for years with only two exception types, and nothing in this issue's acceptance criteria calls for distinguishing, e.g., a 403 from a 422. If callers need finer-grained handling later, `str(e)` on `DecisionAPIError` still carries the original status and message, and new subclasses can be added without breaking existing `except DecisionAPIError` handlers.
